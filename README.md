## 1. Role & Responsibilities

Module 4 is the autonomous cognitive investigation and copilot engine for the Security Intelligence Platform. It operates strictly on indexed events, tracking results, security policies, context memory, and evidence metadata retrieved via the Backend (Module 2).

### Module 4 Owns:
- **Autonomous Security Investigation:** Synthesizing complex security queries into evidence-grounded incident investigations.
- **Security Context Memory Reasoning:** Correlating spatial, temporal, and operational context (e.g., restricted zones, shifts, camera placements).
- **Evidence-Grounded Risk Reasoning:** Deriving risk strictly through: `OBSERVATION -> EVENT -> CONTEXT -> POLICY -> RISK -> EVIDENCE -> CONFIDENCE`.
- **Cross-Camera Investigation:** Correlating tracked entities (`entity_id`) across cameras without hallucinating real-world personal identities.
- **Incident Timeline Reasoning:** Constructing immutable, chronological timelines with exact timestamps and provenance links.
- **Evidence Provenance & Sufficiency:** Verifying evidence completeness, checking for contradictions, and tracking sources.
- **AI Security Copilot Intelligence:** Answering contextual security queries with structured fact/inference separation.
- **Unknown / Insufficient-Evidence Handling:** Explicitly declaring `UNKNOWN` or `INSUFFICIENT_EVIDENCE` whenever observations are incomplete or cameras are offline.

### Module 4 Does NOT Own:
- CCTV / RTSP / ONVIF camera connections or direct hardware control.
- Video frame decoding, YOLO/object detection, person re-identification inference (owned by **Module 3 — AI Video Intelligence**).
- Direct Main Database ownership, table migrations, or persistence ownership (owned by **Module 2 — Backend Security Core**).
- User authentication, JWT issuance, and RBAC enforcement (owned by **Module 2 — Backend Security Core**).
- Frontend UI rendering and direct client connections (owned by **Module 1 — Frontend Dashboard**).

## 4. Absolute No-Hallucination Triad

Every investigation output strictly segregates conclusions into three clear categories:

1. **OBSERVED FACTS:** Concrete data points directly verified from authoritative video intelligence events, camera logs, or evidence metadata.
2. **INFERENCES:** Deductions derived by applying security policies and context memory to observed facts. Must be explicitly flagged as inferences.
3. **UNKNOWN INFORMATION:** Information that cannot be verified due to lack of evidence, camera blind spots, offline status, or low sensor confidence.

> **Absolute Rule:** If evidence is insufficient, prefer `UNKNOWN`. Output: *"I don't know — insufficient evidence to determine this reliably."* Never fabricate missing information, timestamps, cameras, or identities.

## 6. Evidence Sufficiency & Blind-Spot Safety

Before any conclusion is reached, the Evidence Sufficiency Engine evaluates:
1. Is relevant evidence available?
2. Is the timestamp reliable and verified?
3. Is the camera/source known and connected?
4. Is the event actually observed (not hypothesized)?
5. Is enough evidence available to support the conclusion?
6. Is there contradictory evidence?

### Evaluated States:
- `SUFFICIENT`: Full evidence backing available.
- `INSUFFICIENT`: Evidence missing or incomplete $\rightarrow$ *"I don't know — insufficient evidence."*
- `CONFLICTED`: Contradictory evidence detected $\rightarrow$ *"Conflicting evidence detected."*

### Blind-Spot & Camera Health Safety:
If a camera is `OFFLINE` or `DEGRADED`, Module 4 **never** assumes *"nothing happened"*. It reports:
> *"CAM-XX was unavailable during this period, so activity cannot be reliably determined."*
